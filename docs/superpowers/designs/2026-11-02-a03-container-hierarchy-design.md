## 建议效果与取舍

推荐让工具列表和番剧子页直接落在页面背景上，用标题、间距和必要的分组线组织内容。撤掉没有独立语义的大底板，普通操作行不再各铺一个方块；焦点所在位置仍有清楚的一层边缘，真正承载封面、输入、确认和操作的控件继续保留。

另一种选择是保留大底板、只减轻内层行。它对现状改动较少，但主题、目录和关于等短页面仍留下大片实色空区，番剧作品卡也仍被外框包裹。推荐本稿的开放布局。页面分栏、内容顺序与基础阅读尺度沿用现有设计，不通过全局缩小字号或压缩控件制造“变清爽”的效果。

适用范围为五个工具页和番剧详情的三个子页。Cinema 首页、TMDB 详情 B、文件 C、播放 A 继续沿用已选设计；播放器右侧已完成的 A06 与 A02 焦点规则作为当前基线。

## 统一规则与实现责任

1. 装饰性分组优先用留白；细线仅用于真正的组间分隔。页面默认不出现“外层面板＋行卡片＋行内按钮”的连续围合。
2. 焦点／选中／禁用继续分别表达。操作控件沿用 A02 的单层 2dp 边缘、现有圆角和状态；阅读区域允许透明或轻底，但焦点边缘必须清楚。保持焦点留白和图像裁剪，不新增缩放或动画。
3. 说明栏和装饰层不新增焦点。系统缓存、阅读区域及各真实操作的现有焦点不能因为减底被移除。分集中的行与图标只在实际获得焦点的目标显示反馈。
4. 修改局限在上表布局与需要的局部行资源。移除背景时保留容器对布局、滚动、生命周期和数据绑定的作用，不为减一层视觉背景强行删除布局节点。全局 `cinema_surface`、`cinema_button` 和共享作品卡不统一改透明。
5. `user_component` 承担工具页；`anime_component` 承担番剧子页。现有 `core_ui_component` 的焦点委托与策略继续复用，不新增页面壳、表单引擎或跨模块依赖。只在确需调整导航时修改 Kotlin，不改设置／缓存／业务数据逻辑。

## 页面／状态与验收矩阵

下表保留网页设计的场景与原生验收要求；“已制作”说明设计覆盖，实际实现、DPAD 和原生截图结果统一见执行账本。

| 编号 | 设计场景 | 已制作的状态 | 原生必须验证 |
| --- | --- | --- | --- |
| C01 | `page=cache` | 普通／长路径，焦点在列表或系统缓存 | 双向 DPAD、统计更新、清理确认／取消及返回原焦点；不能为拍照清理用户数据 |
| C02 | `page=folders` | 普通／未设置／长路径 | 选目录、长按清除、开关持久化、选择器返回及禁用状态文字跳过焦点 |
| C03 | `page=themes` | 手动／跟随系统，焦点与勾选分离 | 手动项显隐、保存、取消重启、重新进入持久化与默认焦点 |
| C04 | `page=license` | 普通／长文 | 完整正文／链接不丢失，首／末条和超一屏正文可读可滚动，阅读焦点清楚 |
| C05 | `page=about` | 普通／长说明 | 完整归属与网站动作可达，长内容滚动，返回原入口 |
| C06 | `page=intro` | 普通／无简介／长正文 | 阅读焦点、资料展开、滚动、切页与返回；原服务加载／失败反馈保留 |
| C07 | `page=episodes` | 普通／空／长标题／批量标记，行或独立图标焦点 | 原始分集排序／播放记录／单项标记、全选／反选／退出、列表滚动和空态回到页签 |
| C08 | `page=related` | 普通／空／长标题 | 三列网格与分组、真实封面／状态、跨行／滚动焦点、子详情返回恢复 |
| C09 | 共用边界 | 八页均有 1.0／1.3 字体；无焦点参考 | 同数据／焦点／滚动位置与 240dpi 逻辑视口比对，深色／普通主题及大字体；A02／A06 不回退 |

未给原本无加载／错误状态的工具页新增这些界面，也未重设计现有确认弹窗。实施时仍需回归对应确认、取消、错误和恢复路径；实际服务可用性与完整账号场景单独记录，不能从示例数据推断通过。

## 确认后的任务安排

1. **T1：工具页减层。** 按 C01–C05 去掉局部重复背景，保留布局／业务绑定；必要时增加局部透明普通行资源。验证：资源引用逐一核对，五页同数据前后原生截图；焦点、主题保存和许可内容完整。
2. **T2：番剧子页减层。** 按 C06–C08 处理公共底板和分集普通行／行内图标；共享作品卡不改。验证：简介阅读／空态、分集批量操作与独立图标、推荐网格及页面返回均可纯 DPAD 完成。
3. **T3：可视与行为回归。** 在任务自有 AVD 用相同内容、焦点、滚动位置和逻辑密度查看原生与本稿；覆盖 1.0／1.3 字体、主题切换、滚动、设置持久化及确认／失败恢复。回归 A02／A06 相关焦点与播放器返回链。验证：每个矩阵项分别记录截图、DPAD 结果与未覆盖条件，修复非预期几何／可读性差异。
4. **T4：工程与证据收口。** 构建 Debug／测试 APK，执行改动范围所需 JVM、`lint`、依赖治理与限定格式检查；只有出现行为回归时补充能复现问题的测试。验证：读取 Gradle 尾部，明确 `BUILD SUCCESSFUL` 或 `BUILD FAILED`；将实现、构建／测试、视觉、DPAD、用户／实体电视验收分别记录。
