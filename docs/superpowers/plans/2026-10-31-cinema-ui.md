# 沉浸放映原生 UI 改造

日期：2026-10-31。用户确认完成整套界面，包含首页、媒体库、来源、设置和播放控制。依据为已选的 [cinema 网页原型](../../../document/prototypes/tv-ui/README.md)，数据与播放契约沿用 [TMDB 设计](../designs/2026-10-31-tmdb-media-library-design.md) 和 [UI-readiness 契约](../designs/2026-10-30-ui-readiness-repairs-design.md)。开始基线为 `b1ae53e8e`，工作区干净；本地 TMDB 令牌已配置，不写入文档或提交。

## 实施顺序

1. 共用视觉：深色表面、圆角、字体层次、按钮和焦点反馈；沿用默认深色模式，不覆盖用户已保存的主题偏好。
2. 首页与媒体库：大背景、明确的继续观看动作、横向继续观看卡片、海报和详情层次；空库保留真实文件入口，不加入示例内容。
3. 来源与设置：来源操作移到可达的页面头部；设置分类和内容分区，复用已有 Preference 与持久化，统一文件页和弹窗外观。
4. 播放器：渐变控制层、时间进度和按钮分组、圆角侧面板与轨道项；保留 Surface、轨道、字幕、弹幕、播放进度及返回语义。
5. 验证：构建 Debug/测试 APK、受影响 JVM、lint、格式与依赖/播放边界；真实 TMDB API/图片联调；任务 AVD 纯 DPAD 核心路径、设置持久化、返回焦点及两个播放内核回归。

## 验收约束

- 所有操作可使用遥控器到达、反馈和返回，图片/状态更新不跳焦点。
- 使用实际 Room 与服务数据；测试夹具明确标记，仅用于验证。
- 不添加跨作品队列、后台扫描或新存储协议，不重新设计解码/字幕架构。
- AVD、真实网络和物理电视结果分别报告；缺失的真实来源/电视环境不声称通过。
- 无提交或发布请求；保留工作区供用户审阅。
