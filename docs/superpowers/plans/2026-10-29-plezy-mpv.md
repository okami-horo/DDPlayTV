# Plezy mpv AAR 接入与验证

## 目标与范围

用户于 2026-10-29 授权在 minSdk 25 升级后完成 mpv 适配。采用 Plezy 的原生 Android AAR，替换自维护 mpv JNI 与配套 mpv/FFmpeg 二进制；保留播放器业务接口、Media3 默认内核、SurfaceView 硬解直出、应用自有 libass 字幕叠加层及弹幕。设备基线为 Android 11，不新增 Flutter、GPU 视频回退或软件解码策略。

## 依赖证据

- 直接下载 Plezy 当前锁定的 `mpv-android-127aea1231b8.aar`，SHA-256：`60aa28e89ca288d7a653a6a7c50c9dacaa91c4d992868b257f305b909bb26d59`，已核对。
- 对应源码：`edde746/mpv-build@b15bf59c043b45f9ad7fa227b2cc7d3164daf58f`。AAR 内 mpv 标识为 `v0.41.0-dirty`，具体补丁以该提交为准。
- AAR 要求 minSdk 25 / compileSdk 36，Java 字节码 17，Kotlin 元数据 2.4。项目仍使用 Kotlin 2.2.10 / AGP 8.10.1；直接将 AAR 放入 Kotlin 编译路径的探针已失败（`.tmp/plezy-mpv/metadata-probe-retry.log`），不能通过跳过元数据校验掩盖。
- 使用 Java 包装模块隔离上游 Kotlin 类型和编译路径，保留原版 AAR 作为运行时依赖；实际编译、JVM 与设备运行已验证该方案。

## 实施顺序

1. 固定依赖及 Java 边界：校验产物；验证 Kotlin 消费端不读取上游元数据，AAR 的 JNI、FFmpeg 和 C++ runtime 完整进入 APK。
2. 适配播放器：用上游实例、命令和观察接口替换自有 JNI；后台执行 native 操作，过滤已释放会话和旧片源事件，保留状态/轨道/字幕契约。Surface 交接必须验证销毁、暂停位置、重建和退出。
3. 删除被替代的 JNI、头文件及旧 mpv/FFmpeg 产物；保留自有 libass/OpenCC，核对动态链接及发布打包。
4. 验证 Debug/Release/test APK、全量 JVM/lint、模块和播放边界；运行真实 JNI 帧/Surface 测试及 TV DPAD 播放/seek/返回/重入回归。物理 TV 的 PQ/HDR/不同 SoC 性能需与模拟器结果区分。
5. 更新原生依赖来源、支持参数、字幕说明和项目记忆，记录失败、重试与未覆盖范围。未授权提交或发布。

## 执行状态

生产接入、旧 JNI/二进制删除及本地验证已完成。保留 Media3 默认内核、自有 libass/OpenCC、SurfaceView 和 MediaCodec 直出；不扩大到延期的 Media3/libass 设计。未提交或发布。

### 已修复的实际问题

- AAR 的 Kotlin 2.4 元数据不能直接进入当前 Kotlin 2.2.10 编译路径。Java-only 包装使用 `compileOnly` + `runtimeOnly`，完整编译和真实 JNI 测试已证明该边界可用。
- 原生测试最初过早读取 `hwdec-current` 观察缓存；改为等待观察值，仍要求实际 MediaCodec 出帧，不放宽输出策略。
- 暂停后新 Surface 没有帧：记录暂停时间，交接后精确 seek。原非零位置误差小于 250ms 断言保留。
- HTTP 请求头中的逗号/反斜杠被列表字符串解析改变：改用 `change-list ... clr/append` 传原值。真实本地 HTTP 服务验证原值与换源清空。
- 新增应用级 mpv 测试暴露 `File.toURI()` 生成的 `file:/...` 无法直接加载；桥接转换本地 file URI，保留网络 URL，补充编码字符回归。
- 全量 lint 解析 beta 依赖时发现新 Java 模块缺少 beta variant，第一次最终构建 `BUILD FAILED`；补齐与 release 一致的 beta variant 后最终重跑通过。

任务独立创建 `Pixel_5_API_34` 的只读 `emulator-5558`，SwiftShader、ARM64 translation、普通 UI mode。应用 UI 验证使用临时 1920×1080 / 160dpi；基线为 1080×2340 / 440dpi、非 root。夹具从 `.tmp/lease-fixtures/share/playback-long.mp4` 推送。`.tmp/plezy-mpv/avd-restored.log` 已读回显示恢复为 1080×2340 / 440dpi、uid 2000、UI mode 0x11。控制台 `emu kill` 返回 unknown command，随后核对本次启动的父进程 33600/子进程 25468、AVD 名称、端口 5558 与只读参数，仅关闭该子进程；父子进程均退出，`.tmp/plezy-mpv/avd-closed.log` 确认设备列表已无该实例。只读会话中的安装、权限和设置变化随会话丢弃。

没有物理 Android 11 电视、不同 SoC、PQ/HDR、音频直通或长时性能对比证据；不能据此承诺性能提升比例。API 25/ARMv7 仅构建与产物覆盖，设备运行覆盖为 API 34/ARM64 translation。复杂 ASS、MKV 附件字体和已有真实网络/顺序播放验收边界继续保留，不因本轮测试关闭。
